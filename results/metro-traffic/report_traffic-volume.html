Guide

Run this on your own dataset

TabML-Guard is dataset-agnostic: everything above was produced from a config file and your data — nothing here is hard-coded to this particular dataset (this run was regression). To run it on your own tabular data:

  1. Install once: pip install -r requirements.txt. Optional libraries (xgboost, lightgbm, catboost, optuna, shap, river, statsmodels) each degrade gracefully if absent.
  2. Edit config.yaml — point dataset at your file and name your target column. Usually nothing else needs to change.
  3. Run python run.py --config config.yaml.
  4. Read the fresh results/report.html — this same report, rebuilt for your data.

The config file

dataset:
  source: csv          # or 'openml'
  path: data/your.csv   # your file
  target: label         # the column to predict
  time_col: timestamp   # column giving time order (or null)
split:  {train_frac: 0.6, test_frac: 0.4}
models: {boosters: [xgboost, lightgbm, catboost, random_forest], stacking: true}
tuning: {budget_trials: 40, cv_splits: 3, scoring: null}
drift:  {n_chunks: 10, retrain: sliding}   # none | periodic | sliding
report: {title: My Report, fbeta: 2.0}
task: auto             # auto | classification | regression
random_state: 42
SettingWhat it controls
dataset.source / path / namePoint at a local CSV or an OpenML dataset.
dataset.targetThe column to predict. Task is auto-detected from it.
dataset.time_colSet it and the split becomes chronological and drift runs; leave it null for a random split (drift is skipped).
split.train_frac / test_fracHow much data trains vs. tests.
models.boostersWhich ensembles to try; uninstalled ones skip gracefully.
tuning.budget_trialsSearch budget for Random & Bayesian (kept equal for fairness).
tuning.cv_splits / scoringCross-validation folds and the metric optimized.
drift.n_chunks / retrainTime slices, and whether/how the adaptive model retrains.
report.fbetaWeighting of recall vs precision in the Fβ score.
How to read your results

Start at the verdict panel up top. Check whether a simple baseline is close to the best ensemble (if so, prefer the simple one). In tuning, weigh the score gain against the wall-time cost. For drift, remember input drift (PSI) is not the same as performance drift — PSI > 0.2 means inputs moved, but only a falling accuracy/rising-RMSE curve means the model is actually decaying. Trust the significance tests over raw decimal gaps.

Reference

Glossary

ROC-AUC / PR-AUC
Ranking quality of a classifier from 0.5 (random) to 1.0 (perfect). PR-AUC is more informative when classes are imbalanced.
Fβ score
A blend of precision and recall; β &gt; 1 weights recall more heavily.
Regularization (L1/L2/ElasticNet)
Penalties that keep a model simple. L1 zeroes out weak features; L2 shrinks all of them; ElasticNet blends both.
SHAP
A method that attributes each prediction to its input features, with a sound game-theory basis — used here for global importance and one worked example.
Reliability / error capture
Using the model's own confidence to flag shaky predictions for review; error capture is the share of mistakes caught by that flag.
PSI (Population Stability Index)
How far a feature's distribution has moved from training. &gt;0.1 moderate, &gt;0.2 large shift.
Prequential / walk-forward
Test-then-train evaluation over time: score a slice, then let the adaptive model learn it — no peeking at the future.
McNemar's test
Compares two classifiers on the rows where they disagree; a small p-value means the winner's edge is real, not noise.
